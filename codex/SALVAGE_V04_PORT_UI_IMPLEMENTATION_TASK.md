## 1. 首页只有一版：港口主场景

将目前固定四底栏，改为**单一 HOME 港口场景**：
- 顶部常驻 `燃料 / 耐久 / 零件 / 货舱` 和设置入口。
- 港湾静态像素场景（背景单独一张）与当前已装备飞船（独立透明 sprite，飞船购买/切换后换图）。
- 悬浮/圆形四入口：**货舱、商店、飞船、任务**。支持小屏与刘海/手势区；按钮点击区≥44CSSpx、文字可读，背景是装饰不拦截点击。
- 底部一个固定醒目主 CTA：**出发**，避免“打开二级页→找出发”。在港口的功能层点击返回始终回这个 HOME，不要再渲染第二套首页。
- “航迹/航记”降为二级历史/设置，不占首页按钮、**不删除已发生历史**。
- 点击商店、任务、货舱、飞船打开对应同主题面板/页面，保存与取消按真实状态处理。

**像素资产规范**（详见规格文件）：港口背景逻辑192×320→384×640@2x；飞船原96×48、物件图标24×24；同一个1×像素网格与统一调色板，整数导出 + nearest-neighbor；不允许“一张满是画死按钮的概念海报”冒充可交互 UI，也不许在用户看不到的角落用超小文字凑信息。船、车间、仓库可以静态，暂不做耗性能的全景动画。

## 2. 飞船商店（真实多飞船，可买可换）

- 至少3款真的不同的 `shipId` / 独立图/属性/价格/拥有状态的飞船：轻型拾荒船（原始）、中型货船（容量向）、深航探测船（航行向）；重型工程船如展示必须真实可买或明确未开放，不能假按钮。
- 同一库存：`ownedShipIds`、`equippedShipId`（或等价）和船舶等级/升级记录，统一权威配置，购买只扣一次，换装不再收费。
- 购买前展示**实际飞船变化**（货舱空间、油耗/返航预算/耐久加成）、价格、当前余额，余额不足明确禁用；确认后真实提交，一次到账。禁用“假买了但没属性变化”的视觉升级。
- 旧 0.3 存档与已购永久工具必须迁移到默认拥有的原船；已购买的多船必须在刷新、重开和跨版本恢复后保留。出入仓容量不兼容时：不能强行切到小船、吞货或把多余货物塞进隐形免费仓；给出“先出售/整理”提示。
- 飞船改装具体可做：货舱扩容、外置托盘（要有独立可验证的实际容量与放置限制）、引擎/燃耗、耐久强化。**至少一个真正影响玩法的容量改装在本轮可操作**，其余若不实现不得以可购买状态呈现。
- 概念图中的8,000/18,000/32,000及示例属性不是经过审核的数字。参数放 `design/star-salvage/` 或 `src/balance.js` 单一配置，先基于当前12,000船款与现有收入测算再选择；不要偷改已确认油耗与委托收益而不记录差异。

## 3. 任务面板：玩家手动接取

- 港口独立“任务”悬浮入口，展示真实任务卡，清楚标注 **可接 / 进行中 / 已完成 / 已领取 / 已放弃**，每张任务显示目标/奖励/占用的任务槽/期限（无期限就不要凭空加倒计时）。
- **只有玩家明确点击接取**才创建任务及任务槽绑定。未接取也能出发；没有默认自动领取测绘记录箱和180奖励。
- 把原测绘委托转为玩家可主动接取的首项任务。可增加运送零件、深航回收等2个真正可完成的新任务；如果实现不了，标明后续未开放且不能假装可接。
- 对旧存档迁移：在途旧任务 `missionSlot`、`run.contractActive` 仍保留已接取；已完成奖励不再发、已弃任务不复活。接取/完成/领取/奖励/放弃必须经 revision/nonce 或等价唯一任务标识与数据库单事务结算；两标签不会双领，取消不会洗随机风险。
- 不给任务系统增加真实广告、社交、联网、内购或强制倒计时。

## 4. 港口商店与一键补满

- 商店首页分栏：**补给（燃料、维修） / 常规货物 / 飞船商店入口**；“飞船”悬浮按钮直接打开当前飞船/换船/升级，两个路径共享同一飞船事实。
- 燃料、耐久在原有少量补给之外加 **一键补满**。提交前显示 `当前值 → 100 / +n / 共花n×单价零件`；不足钱就按钮不可作为“补满”执行，另有“按余额补到X”时必须明示实际数量/价格。
- 一次补满只提交一次持久化操作，避免原每20点击多次；防连点、多标签及重绘引发双扣。支付后 HUD 和店铺状态原地更新，不把视口滚回顶部。
- 船款/还款降为二级财务菜单，保留自愿还款及旧账，不用大段文字压过货舱和商店。

## 5. 每件货有真实像素样子，不再只有一个方块

- 新增至少8个**有辨识度的原创货物 sprite**：金属箱/能源电池/导航芯片/损坏引擎件/医疗箱/备用燃料罐/观测样本/维修工具箱。每件有稳定 `itemId` → `spritePath` 映射，展示时有“用途/已知价值/面积”。
- 核心区分：**像素 icon** 是物品外观；`shapeMask` 是真实1～8格几何形状，不要求一个格子的物品只能画一个单色方块；多格物件只显示一个物件形象与真实轮廓，不在每格都重复小图标。
- 沿用 0.3 自动合法收下/冲突展开/拖动/旋转/确认；更换已选物、放弃/出售/可消费用品必须有效。旧物件有稳定不剧透的兼容外观映射，不丢历史 UID、名称、价值、形状、来源。
- 画面需可辨认真正的物品，不允许把概念板的缩略图生硬抠下来，包含坏边/背景/写死文字的图片不得入运行 asset。制作独立源图 `@1x` 与无损整数倍导出 `@2x/@4x`，所有运行图片可正常 decode，不使用第三方游戏素材。

## 6. 航路与返港整合成场景式交互

- 出发后在**场景式航路**上显示当前坐标和两个已知信号的悬浮节点，点候选只展开风险/前进油/返程油/余油卡片，再确认才航行；不要恢复底部固定“航路”Tab。
- 仍使用原 `quote`、`homeCost`、逐跳加价和返航油储备，未揭晓信号/剧情不预先显示；不因省掉航迹页面删除真实地图、记录或 RNG 状态。返航仍需确认。
- 返港将收获、卖货、补给、下一任务或下次出发放在主要操作区域；详细账本可展开，扣款逻辑与显示同源。
- 首页/场景/子面板往返均要保持滚动与未提交草案，刷新不重抽候选、不重新发奖励。

## 7. 推荐代码落点与阶段顺序

**阶段 A｜数据与向后兼容。** 在 `src/engine.js` / `src/store.js` / `src/cargo-layout.js`、配置文件先实现下一 schema 的任务状态、飞船归属/配装、容量变体/托盘、资源补满报价。提供迁移、权限与失败保护；不能通过换存档命名空间重开档。

**阶段 B｜原创分层素材。** 在已核对概念源图后制作 `assets/v04/` 静态港口背景、遮挡前景、3+飞船和8+货物的可用像素素材。每个输出在清单登记来源/1×尺寸/整数倍率/PNG摘要、真实加载成功和裁切安全。

**阶段 C｜主界面与功能层。** HOME 替代四Tab，四圆形入口+出发；实现商店、飞船商店、船体升级、任务板、货舱编辑器、场景式航路及返港。真实按钮状态不能与底层引擎脱节。

**阶段 D｜验证与平衡。** 在隔离 QA 档：
1) 0.3 `schema2→3→4→新schema`，以及真实 schema4 进行中/已完成/弃任务、满货舱、升级后降容、钱不够、重复刷新、多标签；保留全部旧货/已购权益。
2) 2趟不导入、不改种子的自然游玩录像，手动接取/未接任务出发两路径、买船/换船/升级/一键补满/自动装载/返港与出售。
3) 真实HTTP Chromium/WebKit × 360×800 / 390×844；18px大字、安全区、手势、滚动、键盘导航，至少4个关键画面（HOME、买船、任务、带真实图标的货舱）。
4) 实际运行画面与**同一张用户认可主界面**对比：构图、比例、色彩、飞船层次、图标与四悬浮入口，逐项指出偏差；PNG展示不能代替点击测试。
5) 经济平衡：含成本、库存、购船与货舱扩容的收支模拟，估算解锁进度；变化需说明，不擅自取消真实油耗和债务。
6) 测试仓库旧主游戏、剧情首章、上一版 salvage 都未受影响；原 CI / 权威登记不删。

**阶段 E｜交付。** 新独立提交 + 固定ZIP/来源 SHA/校验日志/截图录像，并有真实HTTP版本回读。按已经授权的开发自测工作流上传 **新的 TapTap 开发自测版本**，保存实际新ID/二维码/文件名/字节/竖屏/未发布回执；替换同一用户Mac 4283 试玩入口，先保留原服务和用户的私有旧档，只在已确认来源的原 profile 中验证迁移。失败/权限阻塞立即保留 0.3 而不谎称已升级。PR保持 Draft，不合并、不绑定正式主包、不提审、不正式发布。
