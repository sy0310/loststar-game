# Codex 实施总指令（可直接交给 Codex）

仓库：sy0310/loststar-game
设计基准：design/v0.1-spec-and-codex-20261102
工作方式：创建 codex/v0.1-vertical-slice 分支，提交 Draft PR；不得擅自合并/部署。

## 目标
按照现有批准设计，把《失物星球》做成高完成度、高像素密度、2.5D/伪3D 小星球自动探索的竖屏 H5 游戏。特色是“飞船自动探索怪诞星球，每次回来带回完全搞不懂用途的宇宙奇物”；玩家核心动机是发现未知星球、怪诞生物与奇物，而不是纯金币增长。

## 第一件事：先处理参考设计图
1. 读取 README、AGENTS.md、全部 docs/、design/README.md 与 design/ASSET_MANIFEST.json。
2. 从用户提供的《失物星球_V01_完整美术设计稿.zip》导入 16 张编号 PNG、3 张参考 PNG、1 段 MP4、原始设计说明和 HTML 浏览页到 design/reference/v0.1/。**如果工作环境没有 ZIP，立即向用户明确指出缺失，先完成仅依赖文档的步骤；绝对不要假称图片已在仓库或用重新生成的图片冒充原稿。**
3. 用 ASSET_MANIFEST.json 验证尺寸、文件大小与 SHA256 前缀；成功后更新 manifest 状态。
4. 制作 design/asset-review.md：逐页列出“已认可/待优化/仅供概念参考”，注明出图含文本错字、AI 生成拼版不是正式 sprite 素材。
5. 不要直接拿整张设计图做大背景或把角色从复杂背景硬抠到游戏里。

## 第二件事：先达到真实的精致动画表现
1. 先只做“退货箱星/退件平原”一个星球的完整球形 2.5D 场景，图层独立、材质精细；和参考图的高像素密度、暖橙紫蓝色彩接近。
2. 飞船失物号 LR-01 在星球外围椭圆轨道自动飞行，绕到背面必须被球遮住，绕到正面时自然出镜，不能只让整个底图摇晃。
3. 机器人咔哒-07 沿可见地表巡逻，自动进行“行走→扫描→拾取→返回卸货”循环；拆封鼠、包裹、旗帜、雷达用少量动画帧表现生命力。
4. 重视机器人/地形/建筑遮挡；必要时调路径、镜头和建筑位置，不可让角色透墙或悬浮。
5. 输出 8–12 秒动态预览与 4 张遮挡关键截图，和概念图对比，先让用户审核视觉质量；不合格先优化，不要堆功能绕过美术问题。
6. 如果尝试 Three.js 真 3D 球体，请同时给轻量 2.5D 方案对比（画质、性能、实现难度），在移动端表现好才保留 3D；不强制升级成复杂开放世界。

## 第三件事：实现首版完整的玩法骨架
- 页面：基地、未知星域雷达、远征、图鉴、收藏/奇物详情、设备升级、离线归航/事件弹层。
- 核心循环：雷达自动搜索→异常信号→锁定→揭晓未知星球→进入区域→机器人自动探索→收藏图鉴→基地展出→设备升级→继续发现。
- 未发现星球 **不能预先显示数量、方位、名字、图片、问号节点、星球剪影**。游戏可以预置六星数据，但 UI 完全隐藏，只有雷达真实发现后才揭晓；在存档中持久化。
- 收集分奇物、生物、事件、已发现星球；少量奇物具有幽默的“试一试”互动；新的里程碑可保证新发现。
- 飞船/雷达/扫描/回收升级要真正改变效率；先用明确标注的可调测试数值。
- 离线收益、重复打开防双领、刷新保留进度；本地存档足够，结构便于后期迁移。
- 使用配置驱动的 Planet、Region、Discovery、Event 数据模型，方便之后扩充六星内容矩阵；内容不写死在 UI。
- 原则：不实现复杂战斗、自由行走、联机、重生产链，不接真实广告，不复制《无人深空》具体美术或资产。

## 第四件事：测试和交付
- 推荐 Vite + TypeScript + PixiJS（或经比较后 Phaser），UI 可用 DOM/CSS；仅有价值时引入真正 3D。
- 在 360×800、390×844 竖屏和桌面浏览器验证阅读性/操作区域，按 docs/06_ACCEPTANCE.md 做检查。
- 自动化测试涵盖雷达不剧透、保存恢复、离线不双领、正常升级和图鉴收集。
- 给出 build/test 命令、编译通过结果、动效录屏、页面截图、资源包体积和未测真机项。
- 先提交可审核的阶段性结果，再补齐六颗星球的可配置内容；不以“六颗星球全解锁截图”冒充新手体验。
- 将所有改动推送到分支，创建 Draft PR，PR 说明包括完成项、资产导入覆盖率、视觉对照、测试结果、已知限制。**不自动合并、不自动部署。**
