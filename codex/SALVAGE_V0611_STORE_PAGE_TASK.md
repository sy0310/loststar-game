## 1. 为什么做

TapTap 公开页（2026-11-19）：热度 1、关注 2、0 评价，创作者视频 0 播放。问题不只是没人看到，而是看到的人也看不懂：

- **分类和标签**：分类只有"休闲"，没有题材标签。页面上的"相关游戏"现在是驾考、卡车、赛车模拟器，上线当天则是放置、增量小游戏，推荐系统不知道这是什么游戏。搜"割草"搜不到；同类的"深渊割草者""999秒!幸存者"都挂着"割草Roguelike""弹幕射击"。
- **推荐语**："一指走位，配出你的银河火力。"没有类型词。
- **简介**：首句 40 多字；满是"主动装置""辅助配件""精英战利品中抽取"这类术语；结尾强调"开发测试版"。
- **开发者的话**：以"这是失物号的开发测试版"开头。
- **截图**：6 张图都没有标题字。在 180 像素宽的缩略图里，4 张战斗图只是一团紫色，看不出在发生什么；能读出字的只有两张菜单图，但说明不了好玩在哪。HUD 上还有"11 分钟只击落 4 架"这类不合理的数字（来自 QA 准备存档）。
- **宣传片**："宣传片"位（横版 16:9，用于首页推荐和详情页）一直为空，首页推荐素材用的是静态宣传图。

用验收脚本检查现状，共 19 项不达标（见 `baseline/`）。

## 2. 目标

看到页面的人在 3 秒内知道三件事，并愿意点"试玩"：

1. 这是一款**像素太空割草（肉鸽）**游戏；
2. **一根手指**就能玩；
3. **越打越强**，能进化、能融合。

## 3. 硬约束

1. **只做素材和文案。** 不改游戏代码和数值，那是 PR #3 的范围。拍摄需要的准备存档、录制脚本放在 `design/star-salvage/v0611/store/tools/`，不改 `prototypes/salvage-survivor-demo/src/` 和 `index.html`。
2. **素材来源**：只能用 v0.6.11 的实际运行画面，或已认可的现有美术（图标、主视觉）。不新生成飞船、敌人、角色美术；不用其他游戏的画面、Logo、字体或音乐。
3. **真实性**：
   - 画面里的武器、敌人和效果，都必须在正常游玩中能得到。进阶配装可以用合法的准备存档（与 v0.6.10 图库同样的做法）。
   - HUD 上的数字要合理：航时、击落、等级要能对得上，不能出现"11 分钟只击落 4 架"。
   - 不加速播放冒充原速，剪辑可以。
   - 文案不承诺游戏里没有的东西，比如联机、抽卡、剧情、排行榜。
4. **字体**：标题用得意黑加现有紫金字效；说明小字用系统黑体。不用来源不明的字体。
5. **音乐**：只用项目原创合成配乐（`SurvivorAudio.renderOffline`，来源说明见 `artifacts/taptap-promo-v1/music-provenance.json`）或已批准的两首 MP3。不加人声。
6. **不改验收工具和基线**：`verify_store.py` 和 `baseline/` 下的文件保持原样。
7. **公开仓库**：不提交账号、Cookie，也不提交带个人信息的后台截图。

## 4. 交付物

全部放在 `design/star-salvage/v0611/store/` 下。

### A. `listing.json`（商店文案）

字段与 `baseline/listing-live.json` 一致，媒体路径相对于 `listing.json`。

| 字段 | 要求 |
|---|---|
| `title` | 保持"失物号：星海突进"。可以另加 `titleAlternatives`，给 2–3 个带类型词的名字备选，供所有者决定，但不替换 `title` |
| `category` | `"action"` |
| `tags` | 4–8 个，必须包含"割草"、"Roguelike"（或"肉鸽"）、"像素"；建议加上"弹幕射击""科幻""单机"。不要"放置""增量"，也不要"休闲" |
| `promotionText` | 首页推荐语，6–25 字，必须含类型词（割草、肉鸽、幸存、清屏、射击之一），一句话讲清玩法和爽点。方向可参考"一根手指割草，电网蜂群清全屏"，不必照抄 |
| `promotionTextCandidates` | 至少 3 个候选，每个 ≤ 25 字 |
| `description` | 首句 ≤ 24 字，作为钩子；随后 3–4 行短句讲玩法：一指操作、三选一、进化与融合、15 分钟一局、局外成长。不出现"主动装置""辅助配件""双满级""精英战利品中抽取"；前三行不出现"测试"，如需说明测试状态，放在最后一行 |
| `developerNote` | 写成更新日志：第一行"2026-11-xx v0.6.11 更新"，下面至少 3 条以"·"开头、玩家能看懂的改动，例如首分钟更快、经验自动飞回、卡面更简洁、首局结束就能强化、启动更稳。不要以"这是失物号的开发测试版"开头 |
| `promotionMaterialType` | `"TRAILER"` |
| `platforms` | `["android", "ios", "pc"]`。PC 需要所有者在后台确认能否开启 |
| `sourceCommit` | 拍摄时游戏所在的提交 |
| `media` | `screenshots`、`trailer`、`trailerCover`，可选 `gameplayDemo` |

### B. 截图（`screenshots/`，5–6 张）

**规格**：宽 1080，高 1920–2400，JPG 或 PNG，每张 ≤ 4 MB。

**标题**：
- 每张顶部一个大标题（≤ 10 个汉字），可加一行副标题（≤ 16 字）。
- 字高不小于图高的 5%，保证在 180 像素宽的缩略图里也能看清。
- 标题区不遮挡飞船和主要战斗。

**推荐顺序与内容**：

1. 满屏敌机加一指操作，作为钩子。例如"一根手指 满屏割草"。
2. 三选一卡面（用 v0.6.11 的简化卡面）。例如"三选一 越打越强"。
3. 电网加蜂群清屏。例如"电网蜂群 一扫而空"。
4. Boss 战。例如"Boss 压境"。
5. 进化或融合（黑洞、星环等）。例如"进化融合 火力爆表"。
6. （可选）整备或结算，体现"下一局更强"。

**其他要求**：
- 第 1 张必须是战斗画面，一眼能看出"飞船被敌潮包围，正在清屏"。
- 除三选一卡面外，不用信息密集的菜单截图。
- 保留真实 HUD，数字要合理。

### C. 横版宣传片（`trailer/`）

**`trailer-16x9.mp4`**：
- 规格：1920×1080（16:9），20–30 秒，H.264 视频加 AAC 音频，≤ 100 MB。
- 结构：
  - 0–3 秒：满屏战斗高潮，配大字钩子。
  - 3–25 秒：4–6 个递进镜头，每个 ≤ 4 秒，顺序为一指操作 → 三选一 → 电网加蜂群 → 黑洞或进化 → Boss。
  - 最后 3–5 秒：Logo 加"TapTap 搜索 失物号"。
- 构图：竖屏画面放在中间，按高度铺满；两侧用同一画面的模糊放大或星空主视觉填充。标题放在两侧或上方，不压住飞船。
- 内容：用原速实录片段剪辑，可以加字幕，不加人声。

**`cover-16x9.jpg`**：1920×1080，≤ 4 MB，用宣传片里的真实战斗帧加标题字。

### D. 实机录屏（`gameplay/`，可选但推荐）

**`first-minute-9x16.mp4`**：v0.6.11 普通入口、全新存档的前 30–60 秒。原速，无字幕，无画中画，前 5 秒内就要进入战斗，符合 TapTap"实机录屏"位的要求。

### E. `README.md` 和 `manifest.json`

- **来源记录**：每个素材的游戏提交、录制脚本、视口、准备存档配置、截取时间点、字体和音乐来源。
- **后台操作清单**：所有者要在 TapTap 后台手动修改的每个字段，包括分类、标签、推荐语、简介、开发者的话、截图、宣传片和封面、首页推荐素材改为"预告片"、PC 平台。
- **发布顺序建议**：先把 v0.6.11 发到 TapTap，再同时更新商店资料，避免截图和实际游戏对不上。分类、标签、推荐语这几项不依赖新版本，可以先改。
