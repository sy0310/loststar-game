## A. 用户提出的核心问题与改造目标

现在的手机试玩更像纵向长网页：在货舱中要“向下选货 → 向上看棋盘 → 再向下找确认”；每件货普遍占4/8小格，出发自带4格记录箱，16格货舱实际上容不下多少件东西；地图、事件、返港页面信息分散、确认与跳转频繁。目标不只是缩小字体，而是**让当前决策的物件、空间和操作按钮同屏；让1～3格小件成为常见收获，使拼图取舍真实发生**。

**本轮保持：** 航行→事件→回收→返港→卖货/补给/偿还船款的循环、4×4棋盘总面积、真实航路/报价、已有原创图标和紫灰暖金主题。先不加新星球、战斗、合成、装备词条、广告/付费/统计SDK，不抢跑全面美术重做。

## B. 七项改动（本轮全部实施，不是七个独立提案）

| ID | 要解决的问题 | 实施规则 | 可验收结果 |
|---|---|---|---|
| UX-01 同屏布局 | 资源/说明/棋盘/道具/按钮被长页面分散 | 顶部四资源合成紧凑一行；在货舱优先呈现棋盘、当前待装物/横向托盘、旋转与固定底部行动按钮；简化非必要说明，详细说明可展开 | 390×844常规字号下无需上下反复寻找“选货→摆放→确认”；360×800有合理短屏回退，按钮不被底栏/安全区遮挡 |
| UX-02 真正的细颗粒货物 | 旧`size=1`实际=4小格，`size=2`实际=8小格 | 新货物用**真实格子mask/面积**：1、2、3、4、5、6、7、8小格均可定义；常见1～2格和3～4格，5～8格为少量特殊回收件；可有直条/L/T/2×2等连通形；总货舱仍4×4=16格 | 真实事件可以获得单格、双格和三格货；同船能看到多个小件，而不是主要两三个大块；模型防重叠/越界/伪造面积 |
| UX-03 委托独立槽 | 出航的2×2记录箱提前吃掉25%普通空间 | 测绘记录箱改成**单独任务槽与简洁任务状态**，不占16格战利品货舱；保留“携带/放弃/完成3站/安全返港结算180零件”的真实规则；放弃仍显式二次确认 | 空舱出发后普通货舱仍0/16；不凭空增加已完成记录、奖励或更改旧档委托结果 |
| UX-04 事件小收获 | 大多数奖励为一个大件或资源，整理发生得少 | 在**已发生的事件**内增加若干1～3格小物件与混合形状；部分回收选项可获得2～3件，保留其他“补油/收入/离开”选项；有价值但需取舍，不能每次无代价刷满；不泄露未遇事件 | 前3站能实际遇到小件/多件回收机会（用多个固定种子验证而非虚构概率）；可完整显示新物品的形状/售价/费用，背包逐渐拥挤 |
| UX-05 一键装入 | 每次获货都强制跳完整编辑器 | 若当前货物+新货可合法放入，默认呈现简短“获得物品 + 效果 + **收下并装入**”确认，允许“手动调整”；仅在排布冲突、主动换货/放弃时展开完整编辑；无需变更位置的空舱出发也走紧凑确认 | 正常能装下的奖励：从事件选择到提交只需再一次明确确认，不翻找棋盘；取消或失败无扣钱/燃料/伤害、无重抽、无双领奖 |
| UX-06 拼图操作直觉化 | 选中A后点B被当成把A放到B的位置 | **轻点任意已摆货物=选中该货；轻点空格=尝试放置选中货；拖动=移动物件**；旋转固定在棋盘旁，合法/非法轮廓即时反馈；装载/取消按钮固定可见，托盘横向而非长清单 | 轻点A再点B直接选中B；1次旋转+1次空格点击可摆好；不合法落点不丢货、不造成交易；拖动和触屏滚动不互相误触 |
| UX-07 航行页面压缩 | 航点卡/事件/结算是长文章且页面折返 | 航点默认只呈现名称、风险、去/回油和剩余可用油，详情按需展开；事件插画压高度、选项高度压缩，**真实代价始终可见**；结果页“继续航行”直接转真正的航路地图；返港把收益、售货、下一趟放上方，详细账本折叠；补油维修保留滚动位置 | 一屏能读到主要决策与按钮；不为找选项反复滚动；事件结束后顺畅去下一站；重复补给不跳回顶部；账目仍可查看 |

### 界面结构目标（非要求像素级死板尺寸）

**货舱页：** 一行资源HUD → 当前装载说明（1行）→ 4×4棋盘与就近旋转/整理 → 横向“待装小件”托盘 → 悬停/固定的“收下/确认”和“取消” → 原四个主导航。棋盘和托盘应尽量同时可见；若短屏/大字必须滚动，**只让内部托盘或内容区滚动，主行动按钮永远可见**。禁止把文字缩得不可读、用全屏弹窗强挡棋盘或新增第5个主导航。

**事件页：** 小图+短事件文本（可展开）→ 2～4个短选择及清晰的实际费用/风险 → 当前油量/返航储备和返港动作。不能靠隐藏关键风险来减少高度。

**地图页：** 当前点与下一分叉优先显示；点候选可以预览，真正“前往”才消耗资源；结果页继续后直接显示可选候选的航路地图，不要再经“航行列表→打开地图”两次跳转。

## C. 数据与规则约束——必须先改模型，再改外观

1. **Schema 升级与旧货识别：** 当前旧存档 `schema=3`、`cargo[].size=1`代表4小格，`size=2`代表8小格，不能把旧货误解释成新1/2格。新版本推荐 schema4，新增明确的 `cells/shapeId/mask` 或等价权威面积模型；模型唯一决定占格、总量与冲突。旧物体保留其4/8/12/16格对应面积和合法旧包装，不自动缩小/变现；新获得的货采用1～8格新形状。**不得改名存档KEY来绕过迁移**。
2. **委托单槽：** schema3进行中、已放弃、已完成的委托分别迁移；进行中已有的记录箱从普通货舱合法转入独立任务槽，**只转一次**，不丢掉/复制普通货或任务记录；已放弃的不复活、已领取报酬的不重领。迁移必须兼容`run.contractActive`、`event.context.cargo`、`result`、`history/legs`、`RNG`、`ledger`和`archive`。
3. **先展示已知后果，再原子提交：** 自动装入和手动排布都走原`revision/nonce`、几何合法性和一次性持久化事务。选择取消、手势中断、两窗口竞争、失败写盘：原档和经济值均不变；不可通过取消重抽风险；无自动丢弃、出售或吞掉高价值旧货。
4. **货物与经济分开验：** 保留12,000船款、油耗/返航储备、燃料/耐久上限与当前补给单价作为基准；新小货件和单槽会提高带货能力，必须在固定种子/分层对照中报告单位航次收入、占舱率、弃货率和委托完成率。如需进一步调整价格，列出对照和理由，**不得暗改费用**。
5. **保留权利与边界：** 原始UID、物件名称/价值/能力/来源航次、跨趟旧货和永久工具保持；`schema2→3→4`和直接`schema3→4`均需真实测试。重要剧情掉落不预告。旧正式主包、其他游戏存档与老备份一律不读写。
6. **视觉素材：** 复用当前原创SVG和风格；小物件用清晰可识别的形状与单个物件标识，保持手机阅读性；不复制《背包危机》美术或UI图标。
