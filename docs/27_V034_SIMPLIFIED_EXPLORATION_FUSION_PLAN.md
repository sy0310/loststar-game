## 1. 融合后的体验

玩家打开游戏，看见一颗持续活动的精细像素星球。机器人自动找东西，玩家点几下可以帮它加快勘探。探索带回零件和奇物，零件让机器人、飞船与基地逐步成长，奇物带来收藏、互动和基于真实线索的研究。黄昏、异常来访与清晨修复在同一星球上发生。

**点星球助力 → 探索出货 → 收藏奇物／升级设备 → 看见新动作与新变化 → 继续探索。**

| 设计层 | 融合方式 | 玩家能感受到的结果 |
| --- | --- | --- |
| 点击成长 | 点击给勘探提供短时助力，获得即时扫描反馈 | 几秒内知道点哪里，主动参与有作用 |
| 放置探索 | 自动勘探独立运行，离线按有效时长结算 | 放下手机也有收获，少量点击即可参与 |
| 微缩世界 | 完整球体、独立图层、前后绕轨、居民作息 | 星球本身值得观察 |
| 奇物收藏 | 免费入库、玻璃陈列、轻量互动、可选清理修补 | 每件东西有来历、有动作、有可追溯变化 |
| 昼夜事件 | 机器人、飞船和基地设施自动处置异常 | 昼夜改变生活与事件，清晨看得见结果 |
| 成长反馈 | 数值提升与实际动作、设备或陈列变化对应 | 花费前后看得懂差别 |

当前质量基准继续采用退货箱星／退件平原。未知航路在实际定位并具备可玩内容后揭晓，已有航路永久保存。后续星球进入首星通过审核后的制作队列。

## 4. 点击助力规则候选

点击的对象是当前可见星球。玩家的操作表现为协助扫描与勘探，奖励随实际工作完成入账。

| 项目 | 首轮建议值 | 实施与验证要点 |
| --- | --- | --- |
| 一次有效点击 | 排入600ms基础勘探工作 | 候选值，即时亮出扫描脉冲及进度条的助力段 |
| 输入间隔 | 至少300ms | 同一次触控派生的click只处理一次 |
| 输入上限 | 任意滚动12秒最多5次 | 5次合计3000ms基础工作，鼓励点几下再观察 |
| 待应用助力 | 最多3000ms | 容量、时间戳和动作序号有界保存 |
| 平滑应用 | 每真实秒最多应用600ms额外基础工作 | 基础1倍加助力时最多约1.6倍工作推进，角色动作连续 |
| 修正因素 | 采用实际设施完整度、已生效科研与当前扫描阈值 | 点击与自动探索共用同一套收益规则 |
| 夜间 | 场景点击用于聚焦事件与查看状态 | 处置由原安保模型、实际配置和世界时间决定 |
| 后台与离线 | 已接受助力按有效白天时间消费，最多补算已有队列 | 后台产生的收入按原离线规则归航 |

玩家点下后，下一可绘帧出现贴合咔哒扫描器或当前真实勘探点的反馈。蓝色助力段代表已排入工作，实际工作推进后变成实心进度，任务完成才结算零件。缓冲区满时显示短暂“交给咔哒吧”，正在运行的自动探索仍清晰可见。

基础扫描一轮约12秒时，5次助力共提供最多3秒基础工作，首轮完成目标约9至12秒。机器人、维修与科研修正会改变实际时间。以上是设计推算，样板必须测量首次出货和实际入账时刻。

长期平均额外基础工作上限以约25%作为首轮候选，有限窗口单独计入初始排队量和跨窗口余量。统计必须同时输出接受点击次数、排入／应用／剩余工作量，按滚动时间戳核对，避免把窗口边界突发误报为长期增益。与自动档的对照使用相同升级、损伤、科研和有效探索时间。

### 必须解决的动画联系

当前`ExpeditionScene`根据`cycleMs / tuning.scanner`决定机器人路径。若直接在一次输入中加进度，机器人可能跳位。建议输入先进入有界助力队列，再按真实时间平滑消费，角色沿既有路段连续行动。

- 接受点击后保留当前脚点、朝向和承托关系，扫描器和实际地面产生局部响应。
- 速度在约0.15至0.25秒内过渡，行走、扫描、拾取、卸货各自有完整收尾。
- 阶段切换和任务回绕经过连续接点。进度到100%时，同源结算只发生一次。
- 升级改变扫描阈值时保留已有进度比例，动作速度在路段内平滑切换。
- 减少动态设置保留进度与状态反馈，降低装饰粒子。触控回归检验按压、轻点、滑动、弹窗与后台返回。

## 5. 升级怎样简洁又保留旧成长

主升级抽屉先显示两个容易理解的选择，更多设备按需展开。数据继续采用原四种设备ID与已购等级。

| 玩家名称 | 原ID | 可见效果示例 | 首轮展示方式 |
| --- | --- | --- | --- |
| 机器人 | `scanner` | 一轮12.0秒 → 9.8秒 | “探索更快”，升级前后采样与实际完成时间可对照 |
| 飞船 | `recycler` | 每轮8 → 11零件 | “带回更多”，卸货演出对应实际入账量 |
| 雷达 | `radar` | 现场勘测速度提升 | “其他设备”中展开，与实际信号进度关联 |
| 货舱 | `cargo` | 离线容量2小时 → 3小时 | “其他设备”中展开，返回结算显示有效时长 |

表中为现有`tuning`的Lv0至Lv1示例。升级费用先沿用现有公式，Lv0至Lv1为45零件，首轮验证先测点击新增工作量，再决定是否调价。旧满级档继续按已拥有的等级享受效果。

初期用等级、扫描频率、有效灯效和卸货量表达真实成长，重要工程节点采用明确设备结构变化。展柜四档沿用结构升级要求，逐级具备可辨容器、台座、灯光或舱体变化，原台面和物件锚点可追溯。

## 6. 奇物、能力与收藏的融合

探索让玩家得到东西，收藏让玩家愿意回来。六件奇物继续使用实际玻璃前后层、独立循环动作、铭牌与近景互动。基地首页和独立近景复用同一分层展柜，机器人走向展柜观察、整理、返回。

收据流程仍以真实物件推进。

1. 勘探带回含旧收据的土样，立即计入已发现收藏。玩家可免费陈列与稍后整理。
2. 点击“取出”后运行已有受力发掘过程，纸边脱土、弯转、托起和落托。
3. “清理 40”刷掉独立泥层，露出原有字迹。“修补 120”固定破角与卷根，两处变化可见。
4. 整理后可以稳定展开与对照原码。收到实际P03现场观察才出现可执行的“对照线索”，核验后已知缺失由2项变1项。
5. 原纸签收栏与未来外部签收证明分别记录。新记录必须有来源、时刻和动作ID。

收据自身能力按“能展开 → 能比对已有现场线索 → 能整理已确认记录与待查目标”成长。展开、指向真实标记、核对和折回提供动作反馈。后续科技入口由实际完成的比对解锁，任务票写明真实设备效果和目标。物理修补、证据能力和展柜等级分别保存。

基础查看、试验与已完成记录复核免费。原有藏品直接承接既有权益，已有修补与展柜等级按迁移表映射。其他五件先各确定能力、材料和动作差异，再按收据通过的标准逐件制作。

整理演出可以收起，已开始的操作继续按同一任务状态完成。玩家回到探索时仍可看见机器人和星球活动，整理结果通过收藏标记与一次完成提示承接。

## 7. 昼夜和三居民如何进入简洁主循环

世界时钟继续采用240秒白天、60秒夜晚的现有候选节奏。玩家切页、锁屏和离线使用同一时间来源。

| 阶段 | 场景变化 | 第一层操作与反馈 |
| --- | --- | --- |
| 白天 | 咔哒自动走、扫、捡、卸，居民觅食搬运 | 点星球助力，随时查看或升级 |
| 黄昏 | 球面冷暖转换、仓库亮灯、居民归巢 | 一句“快入夜了”，自动切换场景行为 |
| 夜间 | 机器人跨球面追踪，飞船跟踪照明，设施引导和隔离 | 自动处置，点击关注正在发生的事件 |
| 清晨 | 故障或收容结果留下可见痕迹，咔哒焊补 | 一条实际结果与费用，随后恢复探索 |

完整度0至100、自动维修默认开启、可关闭及手动维修、资金不足部分修复、探索效率下限80%沿用既有规则。自动维修预算和离线上限仍由原模型约束。

三居民各自保留白天觅食、停嗅、抖动、搬运或飞行，黄昏归巢，夜晚休息，清晨恢复。动作可用少量帧与停顿实现。夜间异常按独立形态与行为区分于居民。先以已有第三纸影处置为动作标准，前两次旧巡守和另外两种异常单独登记制作与验收进度。

夜间处置目标是观察异常与设施回应。奇物提供收藏、互动、线索和科技启发，安保行动由机器人、飞船和基地设施承担。

## 8. 零件经济与长期价值

玩家只需理解零件这一种货币，探索工作量和助力队列是内部状态。经验条式的成长感由探索进度、真实收获和设备升级承担。

| 消费归类 | 具体消费 | 可验证价值 |
| --- | --- | --- |
| 修复 | 实际设施维修与奇物一次性清理、修补 | 完整度、效率、材料或结构真实变化 |
| 永久建设 | 机器人、飞船、安保、展柜与基地工程 | 实际工作、回收、夜间表现或空间陈列变化 |
| 自选投入 | 有目标的勘测和科研 | 可取得的现场记录、可对照结果或明确的设备增效 |

新手按原120零件开局，旧档按原余额和权益进入。27,049及更高余额允许继续积累。满级、满图鉴玩家的可选工程必须先提供可见新内容，既有1800／4200／6000预算仅作为待制作内容的研究范围。

| 有限工程候选 | 满图鉴时可提供的实际内容 | 开放条件 |
| --- | --- | --- |
| 地表取证工作台 | 原纸与已取得现场记录并列，侧光或测量视角可切换 | 两份真实记录与可操作对照已实现 |
| 居民观察窗 | 三居民栖台、日夜行为观察与实际事件记录 | 栖台和动作变化实际可见 |
| 异常归档走廊 | 已处置访客与原收件站交接过程可回看、可对照 | 场景、门洞和处置档案已实现 |

上述内容先做单个可玩样板，再核对组件折抵与成本。科研任务票区分新观察、已有记录复核和设备增效，费用、用时、可取消条件、退款及离线规则在开工前显示。当前缺少真实目标的候选进入设计资料，玩家界面优先展示已经能执行的任务。

当前192组安全模拟、48组有限预算投影是前版证据。长期消费价值仍待验证，点击带来的额外收入需要重新模拟。现有正式科研完成逻辑会按分类直接补一个未发现条目，正式证据接入时应改为由实际任务目标和已取得观察产生结果，按目标是否有内容决定开放状态。

### 新模拟矩阵与判定

| 维度 | 必须覆盖 |
| --- | --- |
| 初始资金与权益 | 新手120，5,000，27,049原权益旧档及满级对照，50,000完整旧权益，已有受损、待维修和待归航档 |
| 主动程度 | 纯挂机、每10秒点一次、短时连点、持续0.5／2／4／8次每秒，含被限流输入 |
| 时长 | 0、5、15、30、60、120分钟，8／24／72小时离线及有效货舱封顶 |
| 支出策略 | 积累、设备优先、收藏整理、安保建设、可用科研，自动维修开／关 |
| 中断场景 | 助力未耗尽时切页、锁屏、刷新、跨黄昏、升级、重复输入和多标签竞争 |

每行输出毛收入、点击额外工作量、总零件、维修、整理、建设、科研、剩余、完整度、实际新增记录与重复扣费次数。样板每个活动档配同条件自动档，分别报告工作量、收入和首次发现时间。

通过标准为无负余额、无重复奖励／扣费、旧权益无补交、归航只领一次、维修在原预算约束内。点击收益按接受次数和实际应用量核对，长期增益达到设计上限时由输入限流约束。科研和长期工程分别通过“有内容”和“值得投入”审核。数值安全与消费吸引力各自出结论。

| 昼夜与居民 | `src/game/world.ts`、`station.ts`、现有夜间和居民渲染 | 同时钟、同模型、同场景，夜间状态回执显示实际账目 |
| 保存与恢复 | `src/game/persistence.ts`、主界面保存锁 | 有界助力、版本迁移、重试、多标签及存储失败回归 |

建议新增最小输入状态包含`schemaVersion`、`pendingWorkMs`、最多5个已接受时间戳和单调`actionSeq`。正式字段命名、迁移版本和旧客户端兼容方式在实现审查中决定。旧档默认助力为空，已购等级、资金、收藏、坐标、条件与证据照迁移表承接。

| 旧状态 | 承接规则与检查 |
| --- | --- |
| 零件与四项设备 | 余额、等级和效果逐项一致，新名称指向原ID |
| 收藏、图鉴和展柜 | 已发现记录与已购等级保留，旧物基础整理直接承接，补交费用为0 |
| 安保与基地工程 | 已转换的探照灯／隔离门权益继续使用，历史守护投入按现有等值规则核对 |
| 原纸状态与证据 | 实际条件和有来源证据继承，D1的内置A／B样例保留在隔离审核域 |
| 星图与世界时钟 | 历史航路永久记录，当前世界时间与离线结算连续 |
| 待归航、维修及研究 | 沿原任务ID和账目去重，同一结果一次领取或付费 |

一次输入的处理顺序为读取最新状态并结算到当前有效时刻、核对序号及限流、写入助力队列、推进实际工作、结算完成项、提交一次存档、从已提交结果触发可见反馈。动作时间由应用确定，工作量与奖励由统一逻辑计算。点击助力影响勘探工作量，昼夜、雷达与证据来源使用各自真实时钟和条件。

现有`commitSave`会读最新状态再执行变更，主界面优先通过`navigator.locks`串行执行。但localStorage读改写本身缺少跨标签原子保证，当前无Locks API时直接执行。正式接入需复用现有锁，审查缺少该能力的WebView回退，采用单写者与跨标签协调、版本核对和后台标签只读恢复策略。写入失败时本次内存结果和持久状态分别标记，恢复写入使用同一动作序号。

隔离样板使用一个明确的内存零件账本，整理、升级和维修从中产生实际收支。当前V034分开标示的整理预算与夜班片段账本保留为历史对照，新的融合样板先验证统一账本，再进入正式存档迁移审查。
