# V0.3.1 · D1 两份实际动态样板

按 [PR #2 最新 Review](https://github.com/sy0310/loststar-game/pull/2#pullrequestreview-5755961793) 和 [设计候选的 D1 门槛](21_V03_VISUAL_GAMEPLAY_DESIGN_CANDIDATE.md#8-实施阶段与硬验收门槛本轮不得跳过) 制作。本会话用户已批准方向并授权执行，并明确要求生图交给子智能体、主智能体独立审核。

本次是**可操作的只读美术/动作审核**。复用原 `ExpeditionScene` 和 `MuseumScene`，不读写真实存档、偏好或零件，不替换普通游戏入口的夜守和经济。玩家原有收藏、升级、研究和离线结算继续使用 V0.3 引擎。

## 两份样板

### 原完整球体上的 30 秒邮路处置

| 时间 | 实际动作 |
| --- | --- |
| 0–4 秒 | 箱堆/管道旁纸影显形；原分拣站顶灯报警 |
| 4–10 秒 | 咔哒沿原可见球面邮路绕过仓库，前往事件点 |
| 10–15 秒 | 机器人与纸影保持可辨距离，扫描环、角标和细进度条核验 |
| 15–20 秒 | 纸影连续向手位折叠，进入独立透明收容匣 |
| 20–26 秒 | 咔哒携匣跨区域返回；飞船前轨暖光锥跟随事件点 |
| 26–30 秒 | 原仓库收件口开闸接收、关闸，咔哒回到站前，显示巡守完成 |

飞船沿用已获手机反馈正常的四向精灵、喷口、尾焰和完整前后轨道。后轨不穿球显示探照光；纸影参与同一世界深度排序。两个设施分别承担标记与收件隔离，没有沿屏幕底部排列炮台。

### 收据柜同镜头 Lv0–3

| 等级 | 结构与真实动态 |
| --- | --- |
| Lv0 | 原免费玻璃罩与普通底座；收据轻摆 |
| Lv1 | 加厚黄铜灯座、真实金属铭牌；台座升入、归位后点亮 |
| Lv2 | 罩内宽幅邮政分拣格、独立窄轨、滚轮、纸带与机械臂循环 |
| Lv3 | 新典藏舱外轮廓、分件开合安装、独立透明前后玻璃、环绕扫描机构 |

四档共用原房间台面足点 `(175,526)`，收据中心 `(175,445.9268)`、尺寸 `66.9268` 逻辑像素；近景镜头固定 `(65,290,220,310)`。灯座/外舱分别按实测足宽 124/136 注册，保持比例，不按透明画布中心猜位置。原六个台面不移动，Lv0 直接复用原玻璃。旧已购等级没有重新扣款；正式映射外观需等 D1 审核后接入。

## 美术与独立复审

素材由美术子智能体用内置 image_gen 制作原创透明件，原 PNG、完整提示词、返修记录、实测 alpha/足点/内腔和最近邻 WebP 导出均保留在 [D1 源目录](../assets/src/generated/d1/) 与 [运行时注册数据](../assets/runtime/d1/registration.json)。没有从概念拼版截取生产角色，也没有手工 Aseprite 工程。

主线程复审退回过窄内窗、非空白面板、挤占收据的机械、原型黑底铭牌、遮机器人脸的长标签，以及像弹道的细直搜照线。最终候选以真实运行的同镜头四档和连续动画为证据，不把静态注册审计图当作游戏截图。

## 复现

```bash
npm ci
npm run dev
# 普通游戏 http://127.0.0.1:5173/
# D1 http://127.0.0.1:5173/?sample=night-d1
# D1 http://127.0.0.1:5173/?sample=receipt-d1
npm run check
npm run package:d1
```

普通生产入口直接静态载入原 `main.ts`，既不显示 D1 入口也不请求新展柜贴图；存档迁移与首个模拟时刻维持原启动顺序。开发服务只在显式 `?sample` 时改用 D1 静态入口，生产 D1 包由独立 Vite 配置替换同一个 `index.html` 的入口，不增加玩家战斗页。`package:d1` 生成默认进入只读审核的单入口 TapTap 开发自测 ZIP。私有二维码只在本机 `releases/taptap/` 和本会话交付，不提交公开仓库。

D1 生产预览使用 `npm run build:d1` 后运行 `npx vite preview --config vite.d1.config.ts --port 4187`。先 `npm run capture:d1 -- --rehearse`，通过同 SHA 演练再 `npm run capture:d1`（默认4187）。两段视频使用真实墙钟、独立浏览器上下文、原生触控仿真与短触点标记；不使用测试时钟快进。浏览器测试里的加速时钟只用于自动化，不混入视频。

## 仍需审核与下一阶段

- 真实 TapTap 手机的亮度、玻璃反光、角色辨识度、触控和锁屏恢复需用户扫码验证；桌面移动触控仿真不能代替真机通过。
- 主线程与动作子智能体独立复看后仍保留两点视觉批判：夜色偏温暖紫棕，玻璃高光较克制。Lv2分拣格在手机全景的辨识度也需实机判断；未因自动化绿色而宣称美术最终验收。
- 本次仅一种已有纸影的动作样板，不伪称完成三种新异常。另两种生物、安保/科研底部抽屉、其它五柜四档结构按 Review 先等待 D1 样板审核。
- D1 不计算战果、损伤或维修，不把叙事“巡守完成”当成真实经济结算。审核通过后才把新动作接入原同源夜间模型，并重新核验在线/离线、旧档与维修幂等。
