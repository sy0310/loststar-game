# D1 收据本体与便携收容匣精修

本轮制作四档同身份收据和一个可分层携行的空收容匣。全部原始 PNG 由内置 `image_gen.imagegen` 制作，完整提示词、首版和返修稿均保留。正式候选使用 `receipt-tiers-v2.png` 和 `carry-case-v2.png`。主线程已允许它们进入真实 Canvas 合成审核，用户视觉验收仍待完成。

## 收据本体

四档保持暖米纸、紫棕短横印墨、圆形退货邮戳、右上翻口与右下纸卷。每格627×627，确定性导出为256×256透明画布。按各格可见 alpha16 包络统一中心和高度，再由运行时等比放入66.926829逻辑像素包络。

| 等级 | 可见细节 |
| --- | --- |
| Lv0 | 整洁纸厚、分层卷边、清楚邮戳与柔和纸面体积 |
| Lv1 | 双层纸卷剖面、邮戳压印边缘与较精细的纸层高光 |
| Lv2 | 浅浮雕邮戳环、整洁边线和邮政角饰 |
| Lv3 | 首行和下部邮戳局部铜金属墨、路线暗纹和少量菱形路线点 |

首版在67px审计中显出毛边和皱折，主线程判定其升级语义偏向破旧。v2收敛了这两项表现，将材料差异集中到纸层、压印、浮雕和金属墨。Lv0到Lv1仍较克制，需继续结合实际柜内灯光评审。

四张导出的可见 alpha16 高度均为239px，宽度分别为188、189、186、186px。共同中心为画布(128,128)。共同柔性锚点为(186,48)，UV为(0.7265625,0.1875)，该点在四档实际纸面内，alpha分别为253、252、253、253。

`registration.json.receipts.tiers` 给出每档 alpha 包络、纸面、墨迹带、退货印记、下卷边和原始格坐标。纸面和卷边可按这些区域进行分条弯曲、迟滞和显影。素材中的形变为纸张本身，循环动效由运行时代码驱动。

## 携行收容匣

首版1457×1079原件的可见包络为1167×937。当整件可见高40px时，其安全正窗约32×10.67px，主线程据此要求压低提柄、减薄盖板和缩浅底盘。

v2保持铜框、象牙护角、紫色接缝、青绿小指示灯与同一侧视角。真实源包络为(219,259,1000,653)，安全正窗为(360,475,650,350)。该区域227500个源像素的最大alpha为1/255，可见alpha16像素数为0。

后体、前框和铰盖从同一完整原件经过互斥二值mask拆出，三层均为320×256。闭合重组的alpha最大误差为0，可见RGB最大误差为1/255。掩膜、源裁切和所有锚点写入 `carry-case-registration.json`。

| 数据 | 导出像素或逻辑尺寸 |
| --- | --- |
| 真实可见外形 | 57.342857×37.464逻辑像素 |
| 安全正窗 | 37.175028×20逻辑像素 |
| 双握点间距 | 横向23.448864，纵向5.428571逻辑像素 |
| 左握点 | (106.440945,42.648729)导出像素 |
| 右握点 | (229.118110,71.049327)导出像素 |
| 握点中点 | (167.779528,56.849028)导出像素 |
| 铰盖轴点 | (177.354331,42.349776)导出像素 |
| 提柄基部轴点 | (151.921260,71.647235)导出像素 |

尺寸以安全窗高20px决定。相对最初约54px外宽的制作目标，主线程允许增加约3px进入实际手持审核，为30×18的折叠纸影提供上下各约1px空隙。导出取整带来约0.2px的外宽差异，表格记录实际光栅结果。

`handleBounds` 包含两握点和提柄。运行时可把铰盖里的这一局部再次分出并沿 `handleHinge` 折下。`hinge` 用于整个铰盖，`floorContact` 用于地面接触，`gripMidpoint` 用于双手携行注册。三层始终共用同一原点。

## 真实灯芯与展柜接收面

共同注册文件的 `common.vaultEmitters` 保存原Lv3外侧两盏灯的实际发光芯。`common.floorReceivers` 保存基础罩、黄铜灯座和典藏舱的内底椭圆、前唇分界和来源。

基础罩与黄铜座具有原图紫色实底。典藏舱v3的中央孔也清除了底面，源图留下可测量的内沿。其前内沿采样为源x245/y1332、x300/y1343、x400/y1350、x500/y1352，对应接收椭圆为源(240,1304,520,48)。注册中 `hasBakedFloorFill=false`，运行时先建立该托盘实体面，再接收轻微阴影。材质参考指向黄铜座真实紫色表面源像素(1086,184)。

## 可重复导出与验证

```bash
node scripts/export_d1_refinement_assets.mjs --audit
node --check scripts/export_d1_refinement_assets.mjs
```

脚本保留原始透明通道，使用等比例最近邻缩放和lossless WebP，开启 `exact:true`。四张收据共227254字节，三层收容匣共52078字节，合计279332字节。

导出会实测空腔透明度和同源三层的闭合重组。`audit/receipt-old-tiers-native67.png` 从左到右显示旧图等比版本及Lv0–3，先按真实67px绘制后放大。`audit/carry-case-native57.png` 使用拟定的实际携行尺寸进行透明合成。它们用于素材和像素检查，实际手持、柔性运动、开合、遮挡和玻璃灯光以主线程真实运行录屏为准。

当前文档记录源码素材和桌面审查。TapTap真实手机上的像素可读性、连续动画、后台恢复与发热仍需后续实测。
