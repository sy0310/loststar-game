# D1 收据展柜分层素材候选

只制作未购买收据的 Lv1–3。独立收据仍使用原项目 `assets/runtime/receipt.webp`；没有将奇物烘焙进新柜体，也没有把概念拼版裁成正式素材。原始生成 PNG、失败版本、完整提示词均保留。**这是待审核的 D1 候选，尚未获用户美术验收。**

生成：内置 `image_gen.imagegen`，原创独立透明素材。没有外部下载、第三方游戏图、Aseprite 或手工逐帧源工程。初始三次提示见 `prompts.json`，两次结构纠错见 `correction-prompts.json`，Lv3 清除错误白面板见 `vault-v3-prompt.json`。

## 精确注册

房间坐标为 768×960。展柜真实接触点一直为 **(175,526)**；奇物中心 **(175,445.926829)**、尺寸 **66.926829×66.926829** 恒定，不随等级放大或移动。

所有源 alpha bbox、导出 bbox、物理足点、内腔、局部部件与世界坐标均在 `assets/runtime/d1/registration.json`。不要按画布中心猜测接触点。

| 候选 | 导出大小 | 实际物理注册 |
| --- | --- | --- |
| `receipt-base-l1.webp` | 512×156 | 底宽124，等比例可见高37.10；完整含透明边绘制框(112.455297,488.482553,125.025323,38.093653)。没有强行压到34高。 |
| `receipt-mechanism-l2.webp` | 306×438 | 整体绘制框(136.75,389.609756,76.5,109.5)。底部打印机70×19，位于 y480.109756–499.109756；内部地板足点(175,499.109756)，不是外柜526的足点。 |
| `receipt-vault-l3.webp` | 384×607 | 底宽136，可见高216.36；完整绘制框(105.849894,308.678403,138.300211,218.615178)。安全直内腔(138.484144,390.605196,73.319239,104.923787)，原收据左右各约3.2px余量。 |

Lv2 分拣背板是对原始 v1 邮政抽屉格与横梁的裁片注册，未非等比拉宽。世界坐标 x144–206、y390.109756–408.859756，距离奇物静态包络顶部412.463415仍留约3.6px；底部机械与原包络下沿479.390244留约0.72px。侧轨在固定收据两侧。奇物循环摆动可在机械前遮住少量后层，奇物始终是主体。Lv3 原来的外侧纸轨由更高级舱柱自然遮住，不再往内挤。

Lv3 安装切片：导出冠/中段分界 y155.241946，中段/基座分界 y526.385930；实际 `parts` 使用精确值。不要重复绘制两套错开的基座。Lv2 `leftGear/rightGear/roller/ticketOutlet/sortingCubby` 等局部矩形以导出像素为单位，可驱动真正齿轮旋转与走纸。

## 导出与透明验证

```bash
node scripts/export_d1_assets.mjs --audit
```

脚本按 `registration.source.json` 做可重复裁片、等比例最近邻缩放、保留 alpha 的 lossless WebP 导出。设置 `exact:true`，防止 WebP 编码器为全透明像素任意重写红色 RGB、误导不处理 alpha 的预览器。没有重新绘画金属纹理、添加烘焙奇物或非等比压扁。

当前三个纹理共 **436,314 字节**。源图低透明尘点的 bbox 与实物 alpha16 bbox 分开记录，Lv1/Lv3 仅裁去物体之外的低透明尘点与多余画布，源 PNG 全部保留。透明背景不靠黑色冒充。

导出时实际采样固定收据包络：

| 纹理 | 采样像素 | 最大alpha | alpha≥16像素 |
| --- | ---: | ---: | ---: |
| Lv2 | 72,092 | 0 | 0 |
| Lv3 | 34,596 | 2/255 | 0 |

非零低透明的黑色像素不会遮住奇物；这里不声称每个像素都是精确0。脚本在可见资产侵入固定收据包络时会失败。真实的前玻璃、像素高光、安装分层与循环动作仍由运行时负责。

`audit/*-native-alpha.png` 是先按真实房间像素网格缩放、在中性棋盘做正确 alpha 合成后再最近邻放大的检查图，可看到没有实体红圈或背景色块。`l1-registration-room-audit.png` 是静态物理注册合成，**不是游戏截图或连续动画证据**。最终视觉与遮挡需以主线程的实际同源 Canvas 截图、连续运行视频及 TapTap 复测为准。

## 尚需审核

- 手机缩到约50–60px底宽时，滚轮、柜门与灯光仍是否一眼可辨。
- 顶部分拣背板在原玻璃的前高光下是否足够明显；若不明显先改灯光和反射，保持奇物不变。
- Lv3 新玻璃与金属框真实分层、安装中没有跨柜互穿，且足点始终同台面。
- 源文件没有逐帧手绘图集；齿轮、走纸、灯光、框体装配由真实运行时运动驱动。不能仅以 CSS 或素材存在宣称动画通过。
