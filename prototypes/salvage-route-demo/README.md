## 必须先补齐的技术/产品问题

1. 现有LocalStorage+WebLocks回退不保证所有宿主下的原子多标签提交；须改用可靠IDB事务或明确单写入模式，并验证失败恢复。
2. 当前救援实现会清空货舱，跨趟保留货与“本趟货物”未区分。加来源追踪或符合最新明确损失范围的处理；不能UI说只损本趟、实际删除旧货。
3. 连续奇遇的前置标记需要与实际携带物/真实状态一致，不能丢弃或卖出触发物后仍假装它在船上；不必扩充新故事。
4. 还款、跨航次货物出售、维修/加油后结算摘要要保持实际现金与本航次收入范围一致；不把旧库存价值当作新航次所得。
5. 导入数据的事件/选项/费用和嵌套结构仍需严格校验；异常原档保留，不能静默初始化覆盖。
6. 货舱满、资金不足、燃料和耐久同时不足时的可恢复性，以及短工/救援的套利边界，不能由一个初始场景测试替代。
7. 默认本地反馈问句具有引导性，首测可改为可关闭的中性“本趟主要体验如何”，行为日志与口头答案分开。不要用脚本模拟宣称玩家有再次游玩的兴趣。
8. 样式/真实安全区、返回键和文件导入导出需测实际HTTP/TapTap宿主；下载HTML打不开的用户现场根因未确认。
