# V0.3.7 首星经济模拟

本表由 `npm run simulate:firstplanet` 在运行源码 b7f7326 上运行真实模型生成，采用1秒步长。48行在线采样、12行离线采样，12项检查失败数均为0。JSON中的 `sourceCommit` 记录运行源码提交。

原始数据见 [economy.json](economy.json)、[economy.csv](economy.csv) 与 [offline.csv](offline.csv)。执行逻辑见 [模拟脚本](../../scripts/simulate_firstplanet.ts)。

## 起点与消费策略

- `fresh` 从120零件、空收藏、初始设备与白天开始。
- `restart-27049` 将27,049零件旧源交给新周目模型，新周目余额为120。表中 `archivedParts=27049` 表示关联旧源余额，旧源与当前消费账本分别记录。IndexedDB原值备份和首次事务持久化由 [存储集成测试](../../tests/e2e/first-planet-store.spec.ts) 验证。
- `legacy-27049` 与 `legacy-50000` 是保留原余额的兼容样本。两者已有完整首星收藏、Lv5基础设备与全部原成长项目，奇物沿用已整理状态。本体能力、分拣支线和三个Fusion工程从各自初始状态继续购买。
- 每秒最多选择一个真实动作。按收据整理、扫描/回收Lv1、安保/修复位Lv1、其他奇物整理、本体能力Lv1、现有支线及三项观察、基础设备至Lv3、展柜、基地工程的顺序寻找可执行项目。高价项目待资金积累时，后续较便宜项目仍可先执行。
- 自愿付费动作在下单时留54零件，自动维修继续按真实损伤结算。`idle` 采用自动探索与上述消费，`assist` 额外每秒尝试一次轻点，600毫秒工作、12秒最多5次、3000毫秒队列等实际限制生效。

余额恒等式为 `期初 + 累计毛收入 − 实付维修 − 自愿消费 = 可用余额 + 待领取零件`。在线各时点待领取为0。发现数包括已收录的奇物、居民和事件。

## 审核修正与检查

已修正模拟策略中免费复核持续抢占后续观察的问题，旧档累计自愿消费由14700修正为14970。辨识只在有新增未核对来源时选择，免费支线动作直接按可用条件执行。脚本逐次比对报价与真实扣款、费用分类合计、重复付费、负余额、余额恒等式、原始旧权益、雾布局、签收事实、轻点直接入账、离线容量与重复领取。旧档样本还核对清障后的三项观察完整完成。

上述12项检查失败数均为0。此表记录模型投影，浏览器备份事务、绘制、触控和实际设备表现由对应集成与实机证据分别审核。
