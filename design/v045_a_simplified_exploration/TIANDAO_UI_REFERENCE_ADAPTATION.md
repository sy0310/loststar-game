## 2. 唯一UI视觉规则

保留现有星球、房间、居民、奇物和玻璃美术。统一的是所有操作界面，不重画已经认可的世界。

### 2.1 单一紫灰主题，不再按页面切换浅/深皮肤

首轮固定一套低饱和紫灰界面，暖白文字、暖金主操作。色值是这次实现基准，可在整体同屏复核后成套微调，不能单页自行调色。

|语义token|初始色值|应用|
|---|---|---|
|`--ui-bg`|`#1C1730`|应用外壳/安静安全区|
|`--ui-surface`|`#30283E`|事件卡、详情、设置、设备、记录面板|
|`--ui-surface-raised`|`#3B324A`|卡内分组、次按钮、普通状态格|
|`--ui-border`|`#6A5A76`|细边和分隔线，不外发光|
|`--ui-text`|`#F3EBDE`|主要正文与标题|
|`--ui-muted`|`#BEAFCA`|次级说明|
|`--ui-accent`|`#E8C57D`|一个主要操作、当前选中状态|
|`--ui-on-accent`|`#302337`|金色主按钮文字|

错误/成功允许少量语义色，但不能整页变成红/绿主题。夜晚只改变世界光照，不改变面板皮肤。玻璃、柜框和纸张的天然颜色属于场景/物件，不要求染成UI色。

### 2.2 组件统一，不是只替换背景色

- 一个共享token文件和一组公共组件：按钮、短卡、抽屉标题、关闭/返回、标签、三态预览、进度、提示、禁用/处理中/失败状态。
- 首页、事件、收藏、奇物详情、基地、设备、设置、归航、回看和可选设施的同类UI都使用同一规则。重点检查收藏筛选、建设/科研/照料和旧入口，不只修可拍照的三页。
- 移除旧UI九宫格金边、伪元素框和零散浅色覆盖；不能靠新增大量`!important`继续叠皮肤。所有改动限定正确的应用根，避免影响历史审核页。
- 选中导航不再留下厚金框；只用统一填色/细强调条。主要按钮暖金，次按钮紫灰；关闭和返回使用同一原创图标风格、位置与触区。
- 大字、小字、圆角、内边距、分隔线、焦点状态统一；沿用可读字号和至少44px主要触区，不用缩字挤内容。
- 世界完整可见，顶部安静留白和设备安全区保留；二级页也避开顶部摄像头/宿主按钮与底部手势区。

## 3. 物品清理：取消模拟操作，保留图与结果

### 3.1 玩家流程

`真实发现 → 直接显示A完整物件图 → 点击清理 → 简单处理中 → 真实完成 → 结果短句＋换B整图＋一次短反馈`

随后B→C使用同样机制：原图留到合法升级完成，才换C完整图。中间没有取出界面、土盘、手部夹持、沿路径去污或结构拆解演示。

- 详情主体是一张居中的完整物件图，A/B/C身份、比例、角度和固定锚点一致。背景用统一安静展示面；不为清理再次打开一个装修繁复的实时工作台。收藏室本身继续有柜体与环境。
- 发现后的物品立即可查看其A图；不要求玩家再按“取出”才能清理。旧`buried`/`excavating`等状态须兼容：由真实发现资格触发既有免费流程的一次性合法收束，不在UI直接修改收藏/证据，不新增奖励或费用。涉及免费等待/状态迁移的适配要明确记账与测试，不能静默废弃旧进行中任务。
- 点击付费动作后沿原逻辑报价、判定资格、扣一次、按原时长完成。处理中原图不被擦除/切片/拉扯；可以显示“咔哒正在处理…”及简洁进度，允许退出继续探索。
- **成功文字和新图必须跟真实成功提交同步**，不是按动画计时器先显示已完成；失败、余额不足或资源加载失败不放成功反馈。原有开始/完成收费语义保持，不重复扣。
- 真实完成时显示一句风味文案，如“已被咔哒野蛮清理。”随后整图切换，做一次约0.4～0.7秒的轻回弹/落稳或局部亮一下。切图可有极短淡入，但不是模拟旧图逐像素修复。实际时长为候选手感，不改变业务耗时。
- 不是所有物品都硬写“洗泥”：胶带可写“粘住的灰，终于松口了。”；邮戳“清理完毕，日期依然是昨天。”；铃“擦干净了，还是没人签收。”。风味文案不增加物证、能力或真实签收记录。
- “野蛮清理”只是一句轻幽默，不造成额外损坏、资源扣费、屏幕剧烈震动或全屏闪烁。
- 完成后保留一个已认可的免费互动，例如“轻按铃铛”“拉出一截”。新状态的短登场反馈与免费主动互动是两件事，不要因为砍清理动画把后者也砍掉。
- 关闭面板/后台完成后，再打开直接展示当前真实状态；不重播完整处理、不额外延迟、不重复提示/付款。结果反馈按actionId去重；减少动态时直接换图和文字，无强制抖动。

### 3.2 复用，而非重做

六物18图不重画；状态选择继续同一来源，处理提交后整图切换。未来态只读预览不授予权益。六柜、发现/归航、收藏卡、物品详情读取同一状态。收据缺签仍依赖真实证据；不因“清理完成”变成已签收。
