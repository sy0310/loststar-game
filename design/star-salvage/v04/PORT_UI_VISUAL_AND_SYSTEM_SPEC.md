# 星海拾荒 v0.4 视觉与交互唯一基准（用户认可画风，待 Codex 实现）

**状态：视觉风格方向获用户认可；设计稿并非运行素材；程序实现/经济平衡/手机手感均未验收。**  
**历史运行基线：** 0.3.0 / `799a36e` / TapTap 开发自测 `454472`；Draft PR #2，分支 `codex/v0.1-vertical-slice`。不要把本文件称作 0.4 已交付。

## 1. 一张主界面，不要再出现两套首页

- **唯一主界面：望潮港（HOME）**。静态深空港湾像素背景 + 当前装备飞船在停机坪；没有必要为了视觉而做整场动效。
- 顶部：`燃料 / 耐久 / 零件 / 货舱` 四状态紧凑常驻；角落设置入口。
- 中景：清晰、有层次的空间站主体与停泊飞船；精度中等、可落地，不能粗糙到色块，也不做海报级过密像素噪声。
- 场景悬浮入口：**货舱 / 商店 / 飞船 / 任务**，使用圆形图标按钮，可适配小屏为局部半环或左右分布；它们是覆盖于背景之上的真实可交互控件，不是画在背景中的假按钮。
- 底部主 CTA：**出发**。只有这一个主操作。**取消固定四 Tab 首页导航**，不在游戏中保留两套互相矛盾的“主界面”。
- “航迹/航记”降为设置或任务板二级历史记录，**不占首页快捷入口**。仍保留必要的已发生事件记录/恢复状态，不能删除存档里的航路日志。
- 其他页面（商店、货舱、飞船管理、任务）都是 HOME 上打开的功能层/子页面，统一顶部返回与安全区域，明确返回主场景，保留各自草案。

## 2. 用户已确认的像素画风与尺寸（真实可制作）

**主画风：** 深紫/灰蓝宇宙港口、暖金交互重点、少量青蓝发光；轮廓鲜明、可读、轻微分层；飞船与货物都有明确结构，不用纯几何简笔图替代。统一像素颗粒，禁止背景精细、飞船极粗、图标半写实混搭。

**建议实施的权威逻辑画布（Codex 可据实调整但必须全套统一）：**

| 资源 | 逻辑绘制尺寸（原生像素） | 整数倍导出 | 使用方式 |
|---|---:|---:|---|
| 港口无交互背景 | **192×320** | 2×→384×640；4×→768×1280 | 仅场景层，CSS `image-rendering:pixelated`；中心安全构图，360/390宽可裁边但不拉伸船/建筑 |
| 主飞船侧/斜视独立 sprite | **96×48** | 2×→192×96；4×→384×192 | 透明底，4款各独立源图与停泊状态 |
| 货物图标 | **24×24** | 2×→48×48；4×→96×96 | 每件**独立可辨认**图标；不把多格 mask 当图 |
| 圆形功能图标 | **24×24** | 2×→48×48 | 原创统一描边/块面；文字标签用 HTML |
| 物件形状 mask | 1格 = 1逻辑格；棋盘起始4×4 | 与图标分离 | mask 保留 1～8 格等几何、旋转、碰撞 |

注：192×320 是**静态港口场景的逻辑尺寸**，不是整张手机 UI 分辨率；手机实际用 360×800 / 390×844 CSS 进行 HUD 和按钮排布，避开 safe-area。像素源严格以单一 1×格绘制后整数倍导出；响应缩放采用 nearest-neighbor，不能模糊插值。不要从概念整图直接裁出有文字/阴影污染的飞船作为运行 sprite。

**调色基准（初始建议，实际可取样后冻结）：** 深背景 `#171728`、底紫 `#242039`、结构暗紫 `#38304D`、结构亮面 `#665778`、高光薰衣草 `#9B83AB`、暖金 `#F4C785`、金色高亮 `#FFE0A6`、青蓝 `#8ECFCF`、文本 `#F2EDF4`。不要求“只用9种颜色”，但每张 sprite 共享同一 palette/阴影方向/像素宽度。

## 3. 唯一信息架构与返回路线

```text
望潮港 HOME（唯一主场景）
 ├─ 货舱 → 拼图 / 货物详情 / 扩容入口
 ├─ 商店 → 燃料/维修（一键补满）/ 常规物资 / 飞船商店
 ├─ 飞船 → 当前飞船 / 选船换装 / 购买不同飞船 / 改装升级
 ├─ 任务 → 任务列表 / 手动接取 / 正在进行 / 领取（如规则要求）
 └─ 出发 → 场景式下一航点 → 事件 → 带回物件 → 下一航点或返港 → HOME
      └─ 航路费用/返航仍由同一真实引擎报价；航迹记录留在二级页
```

“商店”与“飞船”入口可以分别负责补给和船坞管理，但**同一飞船库存/价格/归属只维护一套数据**；不能两个入口卖出重复飞船或给出不同价格。

## 4. 需要真实存在的界面与关键动作

### 4.1 商店 / 补给
- 至少燃料、船体维修有 **补充20 / 一键补满** 类似操作；一键补满前显示**当前→目标、实际增加量、真实总价格、余额是否足够**。
- 若余额不足不能显示“补满”后却悄悄部分补给；应禁用并提示，另有明确“尽力补给”选项时另标实际数量和价格。
- 反复购买留在当前区域、HUD和余额原地更新；不跳到页面顶端。补给必须走持久化原子提交防连点。

### 4.2 货舱
- 保持 v0.3 的真实 1～8 格、横向待装托盘、同屏棋盘/确认、拖动/点选/旋转、一键合法放入。
- 展示 **每件回收物有自己真实外观的像素小图**：例如金属箱、能源电池、导航芯片、损坏引擎、医疗箱、备用燃料罐、观测样本、维修工具箱。图像资源按稳定物品 ID 映射，不靠中文名称猜图。
- 可升级容量（例：+4格、外置托盘）；**扩容必须真实改变几何/规则**，不能“多显示几格但存档只认16”。外置托盘的容量/可收纳类型/返航保留规则必须在实现前明确。建议首版先做一项可验证的升级，其他作为后续扩展但商店不可假卖。

### 4.3 飞船商店和换船
- 至少3款轮廓明显不同且有独立 sprite 的可购买飞船：轻型拾荒船、中型货船、深航探测船；可额外展示重型工程船作为后续实际可制作款。
- 商品卡：飞船图、名称、容量/燃耗/耐久差别、售价、持有/使用中/可购买、余额不足禁用；购买需要确认并**只扣一次**。
- 飞船资产归属：`ownedShipIds` + `equippedShipId`（或等价结构），旧档迁移自动授予原始船，所有购买的飞船/永久工具保留。换船必须无二次付费并校验容积：不能切到小船后吞掉已有货物。可禁止切换并解释“先卸货”，不得删除或免费暂存。
- 购船价格和属性 **不得照抄概念图示例数字直接上线**；须写到独立配置并以当前12,000船债经济测算复核。购船与升级是两种不同操作，不要用同一个“升级”按钮冒充买船。

### 4.4 任务委托手动接取
- 任务板展示真实可用的至少2～3项任务（按实际实现能力，可先1项实装其余明确标注未开放，不得把假按钮写成可接）。
- “接取”是玩家主动事务；**未接取就出发不自动给任务箱或结算任务报酬**。返航后依据已接任务的实际目标判断/结算，显示进行中、完成、已领取、已放弃。
- 旧 schema4 的 `missionSlot` / `run.contractActive` 历史任务迁移为一致语义：已领报酬不重领，已放弃不复活；在途老档保留原委托，不强制重开。
- 如限制同时接取上限，界面先显式写出。奖励金钱/货物/燃料必须在账本中原子结算，不能预览即领取。

### 4.5 场景式航路与返港
- 选航点可以用星港周边信号悬浮点/小面板，**不再走固定底部“航路”Tab**。地点风险与油耗必须看得清，候选点击仅预览、确认航行才扣油。
- 航迹/历史可以隐藏，但 **真实历史、油耗距离、返航成本、刷新恢复、未揭晓事件保密** 均不能删。
- 返港优先展示：本趟收获/出售/补给/接任务/下一趟。大账本默认折叠。

## 5. 美术实现落地（不能只贴一张海报）

**源图、图层、可交互 UI 分离：**
1) `harbor_bg.png` 纯背景（不含 UI 字与按钮）；可选船台前景遮挡 `harbor_front.png`。
2) `ship_*.png/webp` 独立透明像素船；主界面按 `equippedShipId` 替换。
3) `item_*.png/webp` 独立透明图；货舱物件图标由稳定 ID 决定，旁边有真实占格 mask。
4) 交互圆按钮/价格/任务/顶部数字由 HTML/CSS 或已验证本地 SVG 实现；保证文字可访问，不将其烘焙到位图中。
5) 产生完整资产清单、源文件、导出版本、背景安全裁切说明。每张图明确 `original-1x` 与 `@2x/@4x`，不混用不同像素粒度。
6) 全部素材原创或有明确许可；概念 PNG 只能做参考，不可直接提取当成最终运行 sprite。
