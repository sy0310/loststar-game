## 0. 实际源码核查：根因而非猜测

| 反馈 | 现行源码的真实行为 | 结论 |
|---|---|---|
| 虫洞缺席 | `engine.js`只有原`homeCost(distance)=3+ceil(distance/2)`，`quote`／`spare`／`finish`／`return`都只认普通返港；`encounters-v05.js`的`foldback_marker`明示“暂时仍按实际油量返港”且属于稀有文字奇遇 | **不是UI漏按钮：功能根本未上线**。这次需真正实现，可见、可用且有同源安全报价 |
| 黑市无损抬价 | `market-v05.js::request`按**每件UID只询价一次**，谨慎/大胆询价费用为0；低价`keep`后仍可`sell`按原价出售。拍卖有挂牌费且可流拍 | 不能同一UID无限重抽，但对多件货可以每件先免费问一次，普通卖弱于“免费先问”，需做全航次机会取舍 |

## 1. P0修复：航点回收物完整可见

- 有可回收物的节点优先显示**真实完整货物贴图**，不让飞船压在前面；普通物品与新增4件奇物都能显示，若一个选择有多件可只突出首件并显示“＋N件”缩略，明确“可回收/可能获得”，不是假装玩家已领取。
- 在“选择后结果”卡增加**实际上船的物件缩略**（仅真实获得的UID），不只列名称；无物品时保持现有简洁场景，不能无中生有。
- 修正通用`.hero img`与`.event-featured-item`选择器优先级，适配`object-fit:contain`、独立`z-index`、显示区域与`overflow`，必要时改为右侧独立货物框，不与船重叠。保持整体96px左右高的紧凑场景，不重新铺一张大海报。
- **不是把PNG放大或改图案**：修复容器尺度、裁切、视觉层级；确保实际`src`由`itemId×shapeId`与真实旋转关系决定，4种奇物和普通1/2/3/4/8格均清晰。
- 真实HTTP Chromium/WebKit的360×800/390×844，模拟物品可得/不可得、物品先看/实际收下、打开选项/刷新、换船后，捕获截图和`getComputedStyle`的`object-fit/width/height/z-index`、物品边界与父框交集证明不裁切、不挡按钮。手机实机依然待用户复验。

## 2. P1实际实装：两处**保证可见**的“折返返航”选项

### 2.1 小游戏友好：不再绑主线/随机抽取

- 以当前废环为唯一探索区域，**第3站与第5站**作为固定“折返回港信标”锚点，随该航次实际抵达保证出现。不额外占用普通2候选航点，也**不替换当地奇遇或回收物**；在对应航点/结果页提供第三个清晰按钮：`折返信标返港 · X燃料`。
- 同页保留`沿原航道返港 · Y燃料`。第3站与第5站外仍按原距离公式返港；不加未授权的“随机第二门伤害”或需要读3章剧情的解锁。
- 候选`X=8燃料`是之前已讨论的值，先对照**8/10/12**等多个耗油方案的经济模拟后冻结。首轮不添加现金过路费、神秘货币、联网和强制动画；第3/5站的固定可达性本身就是对“一路都能免费瞬移”的限制。
- 提前清楚显示“第5站附近有折返信标，抵达后可使用”，但不透露尚未进入的奇遇事件或星球；玩家不会先走到危险处才发现是空按钮。
- **安全预留规则必须与真正可用的返航方法一致**：`returnQuotes(s, projectedDepth, projectedDistance)`列出normal/gate合法报价，`safeReturnReserve`只在**已经可靠保证**到达3/5锚点时计入折返成本。行至非门深度、未启用新版本的旧在途航次仍按原普通返港预留，不可“预计未来可能抽到门”就放玩家透支。
- `quote / spare / checkChoice / event`燃料变化、`return / finish / rescue / log / telemetry / summary / assertState`必须使用同一个真实选择方法；普通`return`兼容旧调用，`return`带`method=gate`才可按信标扣油。到达后`gate`在该站始终可用，**不会因为随机事件使已预留8燃料的门突然消失**。
- 60初始燃料、最低前进费用的可核例：深度3累计前进21、普通返14/折返候选8；深度4累计前进31、普通返19且无门；深度5累计前进43、普通返25/折返候选8，抵达后还有17油，能真实选择8油返回。不同船节油比例/不同额外路线耗油也要用真实模型跑，不能只是文案写“能到第5站”。
- 一旦实际选择折返，同一个事务完成扣费、结束航次、保留真实货物和任务结算；重复点击/刷新/两标签/坏档不能免费回港、重复领奖或异常消失。损伤归零仍走原救援，不用门绕过真实保险规则。
- 旧schema7已在途玩家：不能重新生成已承诺路线/风险；可用“该航次沿用旧返航规则、下趟启用新信标”的兼容策略，明确UI说明。新schema字段按原子备份迁移，保留所有购买、零件、任务、船款、外置舱、所有事件与私有保存。

**必须先给出同组模拟下的到达层级、真实单趟费用、两站门使用占比、收益/债务节奏与旧版差异，再冻结最终8/10/12的值。** 用户已经明确希望能在真实路线上看到并使用虫洞，不能再只交`foldback_marker`文字。

## 3. P1黑市：给一次特殊交易机会，而不是每件免费询价

- 推荐**整趟返港只允许1件物品进行1次特殊交易**：谈价（谨慎/大胆二选一）**或**一次虚构NPC快拍；其他货正常卖。新一趟真实出发与回港后才获得新机会；切页/刷新/反复进入商店/卖掉再买不能重置。
- 这样“把本趟特殊机会用在哪件货”成为核心取舍；低谈价仍可选择留货和普通价售出，但**机会已消耗**，不能再拿另一个物件反复尝试。快拍保留最高5零件实际挂牌费与流拍风险，玩家可以直接普通卖而不受惩罚。
- 现有`market-v05.js`每UID生命周期1次报价与已有`offerId/rng`防重机制必须保留；新`offerUsedRun`或等价航次quota为真实状态、出发/归港/续玩边界清楚，老UID/旧报价迁移后不补发已用资格。不加新币、NPC好感、连锁议价或等待时钟。
- 页面直接显示`本趟特殊交易机会 1/1`，开始前明示“询价或快拍只能选一件；流拍有费，低价留货仍耗机会”，若机会用完普通卖无障碍。避免每件都要求点三次。
- 对普通货与稀奇货做固定种子、不同策略及至少512种子回放。重点指标：每趟按钮次数、黑市使用率、直售比例、报价均值/方差、净现金、退款/流拍、是否存在玩家用反复刷新/换物套利。原`item.value`不变，不能悄悄增加所有旧货售价补偿。

## 4. P1新奇遇和彩蛋：让玩家**实际遇见并知道遇见了**

- 12个新奇遇是真实航点；6个彩蛋是事件附加的轻量文字，不是独立节点。不要告诉玩家“已放进6个彩蛋”却只提供开发者才能看到的日志。
- 在新奇遇**实际抵达时**显示`新发现 / 异常讯号`短标记（历史已见不再当新）；在彩蛋触发时用小型独立`航行异常`卡片/像素信号闪烁/轻提示，一次只需2～3句话，**明显区别于普通事件正文**。可以跳过，不能遮挡选项/回港/货舱，不能插入新的长章节。
- **保底方案候选**：从更新后新开航次计，玩家完成最多2趟达到第2站的合法航行后，至少实际触发1个轻彩蛋和1个新奇遇；平时仍沿用保存的RNG按条件触发。此后若连续若干**符合条件且正常完成的航次**未见彩蛋，再在下一个合法到达节点触发一次保底，不增加现金/免费物品；不可凭刷新或取消出发反复触发。
- 如果没有自然候选，保底只能由既有6类中与当前深度/内容**合理兼容**的轻事件触发，不能在普通补油站假装遇见深空古文明，更不能提前揭示未发现星球的名称/坐标。第一航次新手保护仍可保留。
- 必须记录实际新航次`newEncounterSeen/eggSeen/eligibleRolls`，给开发者独立统计。玩家只看到已发生见闻，不展示“0/6收集表”或六件彩蛋剧透。旧在途和原`rng`保留，不为玩家调整随机种子。
- QA必须包含**不用导入、改时钟、固定玩家RNG的自然至少3趟**，证明一位正常玩家会看到一次明显的新发现/彩蛋；隔离固定种子确认6种彩蛋最终都能触发，各自产生1次记录，不能刷新刷出重复记录或免费物品。

## 5. 交付要求及停止条件

优先级为：**图片P0 → 两处折返门P1 → 黑市机会限制P1 → 新奇遇/彩蛋可见性P1**。可在同一Draft PR作为`0.5.1`小版交付，不再扩张大系统。经济深途差异在加入折返门后**重新拆因对照**，不要未经测算直接调整探测船油耗、旧12,000欠款/飞船价格和旧货值。

一票否决：旧schema2–7或在途真实存档损坏、任何路线能前进却无法依规则安全返港、门费用显示和引擎实际扣费不一致、彩蛋凭刷新重复获得、市场突破每航次机会导致刷钱、物品预览在手机仍被裁切/船挡住。发生这些情况不替换Mac原入口、不上传新的TapTap自测，保留0.5.0/465523与0.4.2/458870回退。
