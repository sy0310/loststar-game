# 《失物号：星海拾荒》v0.5 新方向｜奇遇扩充与轻量太空彩蛋

> 2026-11-11 用户明确调整方向：**小游戏优先，增加奇遇和彩蛋，不制作五章科幻长主线**。
> 状态：**本文件为可执行的内容设计与验收计划；事件名称/奖励为候选，尚非已投产内容或已验证数值**。当前基线0.4.2 / 源码94e606f / TapTap开发自测458870，继续 `codex/v0.1-vertical-slice` / Draft PR #2。
> 本计划**取代**历史 `v05/STORY_GATE_ART_PLAN.md` 的长章节开发范围；旧文档留存审计但不得被Codex作为当前开发指令。此前长主线HOLD保持有效。主项目《失物星球》的首星/首章和其存档不在本范围内。

## 1. 产品目标：每一趟都可能有点新鲜事

主循环始终是：**出发 → 选航点 → 选择奇遇 → 收货/拼格 → 返港卖货 → 补给/升级 → 下一趟**。剧情服务于“这次又捡到什么奇怪东西”，不反过来要求玩家读长篇文章。

- 单次事件**1张小图 + 最多2～3句正文 + 2～3个有后果的选项**；服务型事件可以多1个。
- 一个轻彩蛋原则上是**几秒钟即可看懂的一句话、局部视觉异常或一件小物**；可跳过、不阻碍航路/结算、不强迫读档案。
- 不加入固定主线章节、对话树、全新星球、剧情专用货币、额外任务板、NPC声望/好感度或复杂战斗。保留现有3个普通委托并允许玩家照旧自选。
- 星海神秘感来自空间、重力、时间、漂流站与未知信号。借用科幻类型的**母题**，不复刻某部电影的知名人物、台词、专有船型、图标和镜头。

## 2. 当前代码核对：为什么会重复

`prototypes/salvage-route-demo/src/engine.js` 中 `EVENTS` 当前有**14个模板**（13个显式事件工厂加`station`；其中`dream`为随货触发），`TYPES`包含13种可选航点身份。首站`routeOptions()`硬编码`['tank','plates']`，第二站强制一候选`station`；因此单纯在深航池里增加几十个事件，不会改善玩家最常接触的前两站。当前普通返港按累计前进距离`3 + ceil(distance/2)`、推进报价强制预留返港油，不能为了增加奇遇绕过安全检查。

## 3. 本轮内容规模：12个新奇遇 + 6个轻彩蛋

建议在现有14事件模板上增加**10个常见/中等频率奇遇 + 2个低频奇遇，共26个模板**，并增加**6个非强制的轻量彩蛋变体**。彩蛋不占用一个完整8站航程的额外“关卡”：优先作为到达事件后的附加1句/小物/特殊记录，仅极少数提供玩家主动的附加选择。

上表是开发内容池而非顺序剧情；**不要求依次做完、不向玩家展示“已解锁0/12奇遇”或稀有事件清单**。其中至少8个在1～4站合法可达，保证普通60油初始船也能发现新内容。每个奇遇须有至少两个实质不同的选项（资源、货舱、风险、见闻之一），保留明确的无损离开选项。

### 3.1 六个“星际航行感”的轻彩蛋（仅内部可见清单）

详细触发/文案/防重复规则见 `v05/developer/EASTER_EGGS_INTERNAL.md`。主题分别是：
1. **早到七分钟的信号**：偶尔接到还未发出的短讯；
2. **星图上的空白区域**：记录到一次没有星体的奇怪回波；
3. **反向漂移的杯中液体**：局部重力异常；
4. **无人应答的乘客座位**：空位似乎被提前预订；
5. **从未靠过港的船影**：远方一个模糊的灯光跟着航行；
6. **会变的返航坐标**：一段可以留档、未来可衔接折返机制的伏笔。

这些彩蛋**不可冒充已揭晓新星球**，不显示未发现的星球名称/数量/坐标；与当前隐匿星图原则一致。文字轻幽默而克制，不直接使用流行电影IP原文、外星生物造型或具名梗。

## 4. 航路“看起来不同”的关键改造

**必须改首两站的候选生成，而不仅是事件列表：**
- **首次新档的新手第一趟**可以保留较简单的`tank/plates`路线，以免过多复杂机制；**第2趟起首站**从至少6种风险可控的回收/奇遇/补给候选里生成**两种不同选择**，至少有一项无明显必赔/强制工具的安全选项。
- 第二站不再每次**固定必有`station`**，改为按可验证的低风险权重候选；仍可稳定遇到补给，但不应让“每趟第二站有补给”成为唯一的保命路径。
- 新/旧事件在不同深度和风险层分布，不让12个新事件全部稀有或全部8站之后才出现；旧事件仍能见到，不删除已发生记录。
- 避免同一航次重复相同事件ID；遇见的实际内容、已生成分叉、nonce及风险结果必须在合法事务后冻结，刷新/切页不换。
- **正在进行的旧版航次**需以旧路由池完成：建议在`depart`时冻结`run.contentPoolVersion`；旧档迁移时给在途航次标`v042`，下一趟再使用新池，保证续玩时路线和已见事件不因新版池变化而突变。若迁移不需要新增字段，用等价不改变RNG的方法亦可，但要真实证明。

## 5. 彩蛋出现、记录与小奖励

- 对用户可见的**普通事件不依赖看彩蛋才能获奖**；彩蛋是附加的短句/小视觉变化、可选1次单格纪念品，不能让人因为没刷到而无法买船/接普通任务。
- 建议每趟最多出现**1次彩蛋**，其中3个为纯叙事、2个会改变一条已见航行手记而不改变资源、1个提供**一次性可放弃的1格纪念品**。最后一项仍通过现有`revision/nonce`原子装载结算，不允许满舱时自动丢货、免费暂存或重复刷钱。
- 遵循自然稀有，不允许在QA之外给玩家偷偷固定随机种子；可在首次若干趟设置轻度“未见新事件加权”，但**必须按同一保存RNG一次性计算**，报告实际分布，不在DOM渲染/刷新时抽取。
- 见闻记录只展示玩家**已实际碰到**的奇遇和彩蛋。可提供“奇闻（已发现）”二级只读栏，不新增首页圆按钮，不显示隐藏条目/收集百分比。
- 不添加新的独立经济货币、付费抽蛋或强制广告。

## 6. 物件与像素资产成本控制

现有`v04/v041/v042`已拥有统一24原生像素/格、1x编辑/ORA/2x/4x的物件资产。新增12事件不意味着12张背景、12个新飞船或新的星球。

- **建议只新制4个有记忆点的物件**：彗星标签（1格）、冰霜中继片（2格）、引力旋钮（3格L形）、折叠坐标盘（4格/按现有mask），各有自己的`itemId`、完整连通轮廓及可读小图；其他奖励优先复用现有物件或合法按真实形状重组旧件。
- 事件背景优先复用现有港口/残骸/异常/客舱短图，最多补充2张**小场景局部图**（信标、环带），按现有紫灰暖金画风；禁止随机生成一堆风格不一致的大海报。
- 所有新增源含1×/可编辑文件/2×/4×、SHA、来源、许可/原创说明；保持整件mask一致、旋转角与图像一致、不按格贴重复箱子，浏览器实际解码和触控检查。
- 港口背景清晰度的**轻微原生像素/裁切优化**仍属独立小项；不能因增加奇遇又启动一轮全面美术改造。

## 7. 关于虫洞：保留“好玩”的玩法种子，但不再绑长主线

先把“折返标记”作为**可遇见的导航异常**，获得的只是已见的短记录，不自动降低返港费用。若下一轮决定加入真正的稳定捷径：
- 用**一次短奇遇解锁或两段线索**即可，不要求完成3～5章；
- 普通返港费用仍是原`3+ceil(distance/2)`，折返成本（历史候选8油）要经过不同船/不同深度的**前进预算、事件油耗、救援及经济回放**；
- 不可仅改UI返航价，不可在尚未可靠解锁时把潜在门算入安全油量，不可制造第9站或免费刷奖励；
- 本轮**只提交独立实验/经济对照，不把候选门写进玩家当前运行代码**，除非后续明确批准数值和行为。
